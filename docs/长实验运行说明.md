# 长实验（long_train）运行说明

本文档专门讲：**做 hyper_selector 时新加的“长实验”模式是什么，跟标准实验有什么差别，以及实际怎么用一行命令切换。**

入口在 `main.py`，相关代码：

- `build_scales(experiment_mode, long_train_multiplier)` —— 决定 horizon 是否被放大；
- `--experiment-mode` / `--long-train-multiplier` —— 控制上面这个函数的行为。

---

## 1. 为什么要加长实验

`hyper_selector` 是表格 Q-learning：

- 每 `window_ticks = 20` 个 tick 才结束一个窗口、才更新一次 Q 表；
- 标准 horizon 下，每个规模的窗口数都很少（见 §3 的表）。

可能**Q 值还没收敛，仿真就结束了**，看到的多半是“运气 + 探索”而不是“学到的策略”。

所以加了一个 `long_train` 模式：

- **不改其他配置**（节点数、车辆数、任务率、随机种子都不变）；
- 仅把 `horizon` 按倍率放大；
- 让同一份 hyper_selector 跑得更久，观测它真正“学起来”之后的稳态表现。

> 注意：因为 `task_rate` 不变、horizon 变长，**任务总量也会等比变多**，所以不能直接用 long_train 的 `total_score` 跟标准模式比。要比的是“归一化后的指标”，例如完成率、超时率、平均里程，详见 §6。

---

## 2. 实际命令行参数

`main.py` 里跟“实验模式 / 规模 / 策略 / 输出”相关的参数：


| 参数                        | 取值                                                                                             | 作用                                                            |
| ------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `--experiment-mode`       | `standard` / `long_train`                                                                      | 是否放大 horizon。默认 `standard`                                    |
| `--long-train-multiplier` | float（默认 `4.0`）                                                                                | long_train 下 horizon 倍率，**会被 `int(round(...))` 取整**           |
| `--scale`                 | `all` / `small` / `medium` / `large`                                                           | 选规模，默认 `all`                                                  |
| `--strategy`              | `all` / `nearest_task` / `max_weight` / `time_first_bundle` / `rl_charging` / `hyper_selector` | 选策略，默认 `all`                                                  |
| `--output-dir`            | 路径（默认 `outputs`）                                                                               | 结果根目录，**长/短实验主要靠它分目录**                                        |
| `--save-timeline`         | flag                                                                                           | 额外保存 `*_timeline.json`（不开就只有 `*_replay.json` + `summary.csv`） |


实现位置：`main.py` 第 46–86 行。

`build_scales` 的关键逻辑等价于：

```python
horizon_scale = max(1, int(round(long_train_multiplier)))   # 取整
new_horizon  = max(1, int(scale.horizon * horizon_scale))   # 再乘
```

两点要小心：

1. **倍率是先 round 再 int**，所以 `4.0 → 4`、`3.7 → 4`、`4.5 → 4`（Python `round` 偶数）；想精确控制就传整数。
2. `standard` 下完全不走这段逻辑，`--long-train-multiplier` 会被忽略。

## 3. 标准 vs 长实验下的 horizon 与 hyper_selector 窗口数

`default_scales()`（`src/config.py`）三档基础 horizon：


| 规模     | 节点  | 车辆  | 充电站 | task_rate      | seed     | 标准 horizon |
| ------ | --- | --- | --- | -------------- | -------- | ---------- |
| small  | 15  | 3   | 2   | `0.7 × 0.125`  | 20260401 | 500        |
| medium | 40  | 8   | 4   | `1.35 × 0.125` | 20260402 | 800        |
| large  | 80  | 15  | 8   | `1.85 × 0.125` | 20260403 | 1300       |


`hyper_selector.window_ticks = 20`，所以预计窗口数 = `ceil(horizon / 20)`：


| 模式              | 倍率  | small horizon (windows) | medium horizon (windows) | large horizon (windows) |
| --------------- | --- | ----------------------- | ------------------------ | ----------------------- |
| standard        | —   | 500 (25)                | 800 (40)                 | 1300 (65)               |
| long_train      | 4×  | 2000 (100)              | 3200 (160)               | 5200 (260)              |
| long_train（自定义） | 6×  | 3000 (150)              | 4800 (240)               | 7800 (390)              |
| long_train（自定义） | 8×  | 4000 (200)              | 6400 (320)               | 10400 (520)             |


`main.py` 的最后一段会**自动把这张窗口数表打到控制台**（前提是 strategies 里包含 `hyper_selector`），不用手算。

经验值：

- `4×` 是默认的、调参/复盘的常用基线，medium / large 都能看到比较稳的 Q 表；
- `8×` 起，small 也基本能跑到 Q 表稳定，但耗时也成倍上去；
- 调参时建议先 `4×` 看趋势，最终拿数据时再视情况上 `6×–8×`。

## 4. 推荐的命令组合

### 4.1 单策略 × 单规模（最常用，调参 / 复现 bug）

标准：

```bash
python main.py --scale medium --strategy hyper_selector --output-dir outputs/dev_standard
```

长实验（4× 默认）：

```bash
python main.py --experiment-mode long_train --scale medium --strategy hyper_selector --output-dir outputs/dev_long_train
```

更长（8×）：

```bash
python main.py --experiment-mode long_train --long-train-multiplier 8 --scale medium --strategy hyper_selector --output-dir outputs/dev_long_train_x8
```

### 4.2 全策略 × 全规模（横向对比，做汇报图常用）

标准模式跑完所有策略 + 所有规模：

```bash
python main.py --output-dir outputs/compare_standard
```

长实验模式跑完所有策略 + 所有规模：

```bash
python main.py --experiment-mode long_train --output-dir outputs/compare_long_train
```

跑完后两组目录的结构都是：

```
outputs/compare_xxx/
  small_hyper_selector_replay.json
  small_max_weight_replay.json
  small_nearest_task_replay.json
  small_rl_charging_replay.json
  small_time_first_bundle_replay.json
  medium_*  ...
  large_*   ...
  summary.csv
```

`summary.csv` 中每一行都带 `scale / strategy / total_score / completion_rate / timeout_rate / total_distance / simulation_failed`，可直接拿去画对比图。

### 4.3 “只动长实验、只看 hyper_selector”

通常做 RL 调参时不需要把所有策略再跑一遍：

```bash
python main.py --experiment-mode long_train --strategy hyper_selector --output-dir outputs/hs_only_long
```

会跑 small / medium / large 三档（因为 `--scale` 默认 `all`），输出三份 replay + 一份 summary，省下其它策略的运行时间。

## 6. 长实验数据怎么和标准实验比

直接比 `total_score` 没意义（horizon 不一样、任务总数也不一样）。建议看：

- `completion_rate = completed_tasks / total_tasks`
- `timeout_rate`
- `total_distance / completed_tasks`（单任务平均里程）
- `simulation_failed`（必须是 False，long_train 下尤其要确认电量安全没崩）

另外 hyper_selector 还有专属的“学习曲线”可看：

- `outputs/hyper_selector_trace.csv` 每窗口一行，记录了 reward、Q 值变化、动作选择；
- 跑 long_train 时这张表行数会显著变多，足够画一条收敛曲线；
- 如果想分清不同 run 的数据，每次启动会自动写一个 `run_tag` 列（在 `_run_tag` 里随机生成的 8 位数字），按它过滤即可。

## 8. 一句话总结

> **加 `--experiment-mode long_train` 就是把 horizon 整体放大、让 hyper_selector 真正“跑够窗口数”。**  
> 其它一切（策略、规模、种子、奖励权重）保持不变；要做对比就靠 `--output-dir` 分目录，并且只比归一化指标，不比 `total_score` 绝对值。
